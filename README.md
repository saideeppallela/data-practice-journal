## 🎯 Why I Created This Repository

Learning data tools is easy to measure by the number of courses completed.

**Real skill is harder to measure.**

Can I understand an unfamiliar problem?

Can I break it into smaller parts?

Can I choose the right approach?

Can I find where my solution is wrong?

Can I validate the result?

Can I explain why my solution works?

Can I solve a similar problem without copying the previous solution?

These are the questions I want this repository to answer.

So instead of keeping my learning private, I use this repository as a **public practice journal** where my progress is visible through the actual problems, solutions, mistakes, corrections, and improvements I make.

## 🔎 How I Approach a Data Problem

When I receive an unfamiliar problem, I try not to jump directly to the answer.

I first work through the problem logically:

```text
1. Understand the question
          ↓
2. Identify the required output
          ↓
3. Understand the available data
          ↓
4. Break the problem into smaller parts
          ↓
5. Choose an approach
          ↓
6. Attempt the solution
          ↓
7. Test and validate
          ↓
8. Identify mistakes or edge cases
          ↓
9. Improve the solution
          ↓
10. Document the learning
```

This process is especially important in my SQL practice.

A query producing the expected output is only the beginning.

I also want to understand **why it works, where it can fail, and how I can improve it**.
